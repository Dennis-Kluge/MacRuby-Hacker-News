Hacker News

A Mac app written in Ruby. Real AppKit, no patched interpreter.

Not Ruby generating a user interface

An NSSplitViewController with a sidebar, a unified toolbar with SF Symbols, view-based tables, a WKWebView, the system share sheet — all of it driven from Ruby, through a bridge written for the purpose.

That bridge is the point. MacRuby answered the question “can a Mac application be written in Ruby?” until it stopped working: it depended on Apple's Objective-C garbage collector, which no longer exists, and on an LLVM JIT roughly sixteen major versions behind. Both of those were about being a Ruby implementation, not about talking to Cocoa — and the metadata that makes bridging possible is still shipped and still maintained by Apple, in 216 frameworks. So this bridges to a Ruby instead of replacing one.

The page, beside the comments

⌃⌘3 and the window becomes stories, the page they link to, and the comments — in the order you read them. The page loads as the selection changes, after a pause long enough that arrowing down the list does not ask every site in turn for something nobody waited to see.

Three columns need room for three. When the window has not got it, the article gives way and the list and its comments keep the space.

Search that means it

⌘F narrows whichever section is showing, with a sort and a date range in a bar that appears only while you are searching.

Sorting by date asks precisely, because nothing downstream will rank a bad match down — otherwise a search for “rust” comes back full of “trust” and “restart”. Sorting by relevance stays forgiving, which is what still finds Kubernetes when you type “kubernets”.

Keep things, and take them with you

⌘D saves the story you are reading into a section of its own. What is kept is the whole story, not a reference to it — the API will not necessarily still answer for it months later.

Export the lot as Markdown, JSON, OPML, or a bookmarks file Safari, Chrome and Firefox all import.

And the rest

  • Selectable, clickable comments. Every row is a real NSTextField, so links work and text copies.
  • Endless scrolling through Hacker News's own sections, each on a ⌘-number.
  • Site icons fetched straight from the domain, not through a favicon service — no third party is handed your reading list.
  • A built-in reader with its own history, or your default browser. Whichever you prefer.
  • Refetches on a timer, but only when you have not scrolled away.
  • A customisable toolbar, and a title bar that carries controls and nothing else.

Build it

macOS 12 or later, and any Ruby with a working compiler.

git clone https://github.com/Dennis-Kluge/MacRuby-Hacker-News.git
cd MacRuby-Hacker-News

rake run     # compile the bridge, then start the reader
rake app     # build Hacker News.app, with a Dock icon and a name

There is no release to download: the .app hardcodes the Ruby that built it, so it is not portable to another machine. Building it takes a few seconds.

The bridge underneath

cocoa/ is a subproject of its own — library, C extension, tests and examples. Message sending through libffi, structs by value, Ruby blocks as Objective-C blocks, Ruby methods as real IMPs so delegates and target/action work, and Cocoa exceptions as rescuable Ruby ones.

483 tests across the two, passing identically on Ruby 3.3 under Rosetta and on macOS's own native arm64e Ruby 2.6.
